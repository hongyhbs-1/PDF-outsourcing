# 视觉层级统一方法论

> 基于 T006 实践总结的第一性原理。所有排版层级统一工作必须遵循此方法论。

## 1. 问题本质

**表面替换 ≠ 层级统一。** 把硬编码值换成 var() token 只是工具层面，不是方法层面。

真正的层级问题是：同一个角色（如"模块页标题"），在不同模块里有不同的视觉权重。

## 2. 根因

每个模块的 CSS 是独立编写的。每个模块自己决定"标题应该多大、多粗、什么颜色"。没有一个跨模块的层级角色定义告诉所有模块："你是 Level 0，你必须长这样"。

## 3. 第一性原理分解

一份 PDF 报告的视觉层级，本质只有 **5 个角色**：

| 角色 | 示例 | 读者定位 | 推荐参数 |
|------|------|---------|---------|
| **L0** 模块页标题 | "一、诊断摘要" | 我在哪个章节 | 22px / 800w / 主题色 |
| **L1** 区块标题 | "一、整体情况" | 我在看什么内容块 | 15px / 800w / 深色 |
| **Hero** 核心陈述 | "整体已达标..." | 这个区块的核心结论 | 17px / 700w / 深色 |
| **L2** 卡片标题 | "难度分布" | 我在看什么卡片 | 13px / 700w / 次深色 |
| **L3** 内容标签 | "三角形类型" | 这是具体什么数据 | 12px / 600w / 浅色 |

**统一层级 = 同一角色的视觉表现完全一致，跨模块零差异。**

## 4. 错误方法（已验证失败）

1. 定义 token ✅
2. 替换硬编码值 ✅
3. 希望各模块自然消费 ❌

Token 只是变量名。如果模块不消费它（或消费了但被更高优先级的规则覆盖），层级就不会统一。

## 5. 正确方法：四步法

```
定义角色 → 枚举映射 → 强制声明 → 计算验证
```

### Step 1: 定义角色

在 `visual_hierarchy.css` 中定义 5 层角色的视觉参数（字号/字重/颜色/行高/间距）。

### Step 2: 枚举映射

用 Playwright `getComputedStyle()` 扫描所有模块的所有标题元素，按角色分类每个 CSS 选择器。

工作量估算：10 模块 × 5 层级 × ~3 选择器 ≈ 150 个映射。

### Step 3: 强制声明

在 `visual_hierarchy.css` 中用分组选择器 + `!important` 强制覆盖：

```css
/* L0: 模块页标题 */
.m1-section-title__text,
.m2-cw-module-title,
.m3-kp-drill__title,
... {
  font-size: var(--vh-h0-font-size) !important;
  font-weight: var(--vh-h0-font-weight) !important;
  color: var(--vh-h0-color) !important;
}
```

### Step 4: 计算验证

不是看 CSS 源码，而是用 Playwright 验证实际计算样式：

```python
for h in headings:
    fs = h.evaluate('el => getComputedStyle(el).fontSize')
    fw = h.evaluate('el => getComputedStyle(el).fontWeight')
```

**同一角色的所有元素，计算值必须完全一致。**

## 6. 关键洞察

### 6.1 !important 是必要的

在跨模块层级系统中，`!important` 不是坏实践。模块 CSS 的局部样式不应该能覆盖全局层级定义。

### 6.2 选择器枚举是核心工作量

每个模块用不同的 class 命名（如 `m1-section-title__text` vs `m2-cw-module-title` vs `m3-kp-drill__title`），必须逐一枚举。

### 6.3 验证必须用计算样式

CSS 继承、cascade、@media 都会影响最终渲染值。只有 `getComputedStyle()` 的输出才是真相。

### 6.4 封面/目录可豁免

m0_cover 和 mtoc（目录）是特殊页面，不参与内容层级系统。

## 8. 反模式

| 反模式 | 说明 |
|--------|------|
| 只定义 token 不强制消费 | 模块会忽略 token，继续用自己的样式 |
| 逐文件替换硬编码值 | 表面统一，实际被 cascade 优先级覆盖 |
| 不验证计算样式 | CSS 源码看起来统一，但渲染结果不一致 |
| 按模块设计层级 | 层级是跨模块的概念，不是模块内部的 |
